# 03 — PostgreSQL Schema Design

## Conventions

- PostgreSQL 16+. Single database, one schema `public` (module ownership is enforced in code, documented per table).
- Primary keys: `uuid` generated in the application as **UUIDv7** (time-ordered, good index locality, not enumerable like serials).
- Timestamps: `timestamptz`, stored in UTC; `created_at`, `updated_at` on mutable tables. Display in `Africa/Addis_Ababa` (UTC+3, no DST).
- Optimistic concurrency: `version int NOT NULL DEFAULT 0` on mutable aggregates.
- Status columns: Postgres `enum` types (generated by Prisma) for stable sets; transitions enforced in services.
- Money: `bigint` minor units + `currency char(3)` with `CHECK (currency = 'ETB')` for now.
- Soft deletion: only where history must survive and users "remove" things: `vehicles.archived_at`, `listings` (CLOSED status), `users.closed_at`. Financial, audit, verification and agreement tables are never deleted.
- Personally sensitive columns (licence number, TIN, national-ID-derived fields) are encrypted at the application layer (AES-256-GCM, envelope key from KMS/env) and accompanied by a keyed HMAC column where lookup/uniqueness is needed.
- Constraints that Prisma cannot express (exclusion, partial unique, triggers, CHECKs) live in hand-written SQL inside the Prisma migration files and are covered by integration tests.

## Tables

Only key columns shown. `id uuid PK`, `created_at`, `updated_at`, `version` are implied on every mutable table.

### Identity
```
identity_verifications
  user_id FK, provider text NOT NULL ('FAYDA_ESIGNET' | 'DEV')
  status enum(PENDING, VERIFIED, REJECTED, EXPIRED, SUSPENDED, REVERIFICATION_REQUIRED)
  state_hash text UNIQUE, nonce_hash text, pkce_verifier_enc bytea   -- never sent to client
  session_expires_at, callback_received_at NULL
  subject_hmac text NULL                       -- HMAC(provider sub / Fayda token); no raw ID number
  verified_full_name_enc bytea NULL, verified_dob date NULL, verified_gender text NULL
  claims_hash text NULL                         -- SHA-256 of received claims set, for audit
  assurance_level text NULL, verified_at, valid_until NULL
  rejection_code text NULL, reviewed_by FK users NULL
  UNIQUE (subject_hmac) WHERE status = 'VERIFIED'          -- BR-ID-2
  INDEX (user_id, created_at DESC)
```
Photos, biometrics, address and raw ID numbers returned by the provider are **not** persisted.
Each row is one verification attempt. `EXPIRED` on an attempt means either the 15-minute session lapsed (`verified_at IS NULL`) or a verified identity reached `valid_until`; `users.identity_status` holds the account-level status from 02 §3.2, including `UNVERIFIED`.

### Documents
```
documents
  owner_user_id FK users                       -- uploader
  purpose enum(DRIVER_LICENSE_FRONT, DRIVER_LICENSE_BACK, OWNER_TIN, OWNER_BUSINESS_LICENSE,
               VEHICLE_REGISTRATION, VEHICLE_OWNERSHIP, VEHICLE_INSURANCE, VEHICLE_INSPECTION,
               VEHICLE_PHOTO, HANDOVER_PHOTO, DISPUTE_EVIDENCE, PROFILE_PHOTO)
  storage_key text UNIQUE                      -- random, e.g. docs/2026/11/<uuidv7>
  mime_type text, size_bytes int, sha256 text
  upload_status enum(PENDING_UPLOAD, UPLOADED, SCAN_FAILED, AVAILABLE, DELETED)
  review_status enum(DRAFT, SUBMITTED, UNDER_REVIEW, APPROVED, REJECTED, EXPIRED, SUSPENDED)
  expires_on date NULL, rejection_reason text NULL, reviewed_by FK NULL, reviewed_at NULL
  CHECK (size_bytes <= 10485760)
  INDEX (review_status, created_at) WHERE review_status IN ('SUBMITTED','UNDER_REVIEW')
  INDEX (expires_on) WHERE review_status = 'APPROVED'
```
Link tables carry the domain meaning: `driver_license_documents`, `owner_documents`, `vehicle_documents (vehicle_id, document_id, purpose)`.

## Concurrency guarantees

| Race | Guard |
|---|---|
| Two owners' clicks / two devices accept two applications for one listing | `SELECT … FROM listings WHERE id=$1 FOR UPDATE` + partial unique index on `applications(listing_id)` for active states. Second transaction fails → 409 `LISTING_NOT_AVAILABLE`. |
| Two agreements activate overlapping assignments for one vehicle | Exclusion constraint on `assignments(vehicle_id, period)`. |
| Driver double-taps "apply" on poor network | `Idempotency-Key` + `UNIQUE (driver_profile_id, idempotency_key)` + partial unique per (listing, driver). |
| Charge job runs twice | `UNIQUE (assignment_id, kind, period_start)` with `ON CONFLICT DO NOTHING`. |
| Two payments for one charge | Partial unique on `payments(charge_id)` for live states. |
| Duplicate webhook | `UNIQUE (provider, provider_event_id)` + journal `idempotency_key` derived from provider event. |
| Two payouts drain one balance | `SELECT … FROM ledger_accounts … FOR UPDATE`, balance check, journal move to in-transit in one txn. |
| Lost update on edits | `version` column; `UPDATE … WHERE id=$1 AND version=$2`, 0 rows → 409. |

Lock ordering rule to prevent deadlocks: listing → application → agreement → assignment → ledger accounts (sorted by id).
